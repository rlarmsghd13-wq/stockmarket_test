# 증권사 목표가 수집 — 뉴스 인용 기반

기사에 인용된 "OO증권, 목표주가 N원"을 모아 종목별 컨센서스를 만든다.
한경컨센서스·네이버 금융·네이버 뉴스는 `robots.txt`가 자동 수집을 전면 금지하므로
**공식 검색 API만** 쓰고, API가 주는 제목과 요약문(2~3줄)에서만 추출한다.
기사 본문은 받지 않는다.

## 데이터 경로

| 항목 | 내용 |
|---|---|
| 엔드포인트 | `https://naverapihub.apigw.ntruss.com/search/v1/news` |
| 인증 헤더 | `X-NCP-APIGW-API-KEY-ID` · `X-NCP-APIGW-API-KEY` |
| 한도 | 월 775,000건 (한시적 무료) · 키당 50 RPS |
| 실제 사용 | 199종목 1회 수집에 **387회** — 한도의 0.05% |
| 제약 | 검색어당 최신 **1,000건**까지. 대형주는 그게 약 30일치 |

기존 네이버 개발자센터 키는 쓸 수 없다(2026년 NAVER API HUB로 이관).
키는 `screener/.env`의 `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET`.

원본 응답은 `data/raw/naver/news/{날짜}/`에 남기고, **관측치는 매번 원본에서 다시 뽑는다.**
추출 규칙을 고치면 과거분까지 바로 반영된다(DART 원본을 남기는 것과 같은 이유).
누적 저장하면 옛 규칙으로 잘못 뽑은 값이 계속 남는다.

## 검증 (2026-09-11) — 네이버 증권 컨센서스와 대조

| 종목 | 증권사 | 우리 중간값 | 네이버(평균) | 차이 |
|---|---|---|---|---|
| KB금융 | 15곳 | 220,000 | 225,444 | **−2.4%** |
| 현대차 | 23곳 | 720,000 | 701,600 | **+2.6%** |

기준으로 삼은 ±10%를 통과해 전 종목으로 확대했다.
199종목 중 **148종목(74%)**이 증권사 3곳 이상으로 중간값이 나온다
(0곳 23 · 1~2곳 28 · 3~9곳 81 · 10곳+ 67).

## 실제로 나왔던 함정 7가지

추출기를 만들며 마주친 것들. 전부 회귀 테스트(20건)로 고정해 두었다.

| 함정 | 실제 사례 | 대응 |
|---|---|---|
| **복제** | LS증권 45만원 리포트 하나를 매체 **38곳**이 받아씀 | (증권사, 목표가)가 14일 내 같으면 1건 |
| **다른 종목** | 삼성화재 78.5만·삼성물산 55만이 삼성전자 목표가로 | 목표가 문구 **앞쪽**에 다른 종목명 있으면 버림 |
| **약칭** | "삼전 67만·닉스 470만" | 종목 약칭 사전 |
| **여러 종목 나열** | "삼성전자 등 7종목 매수 추천" | 기사 통째로 버림 |
| **계열사 이름** | KB금융 기사의 "KB증권"은 자회사 | 계열 증권사는 애널리스트로 안 봄 |
| **옛 목표가 재인용** | KB가 현대차를 120만→90만 인하한 뒤에도 120만 인용 | 여러 매체에 실린(복제 2건+) 발표 우선 |
| **증권사명 = 상장사명** | "**키움증권**은 KB금융 목표주가를…"이 '다른 종목'으로 탈락 | 종목명 판정 전에 증권사 이름을 지움 |

마지막 것이 가장 컸다. 키움증권·NH투자증권·미래에셋증권은 그 자체가 상장사고,
LS증권·한화투자증권·현대차증권은 이름 안에 상장사명(LS·한화·현대차)이 들어 있다.
이것 때문에 KB금융에서 진짜 발표 8건이 빠져 중간값이 6.9% 낮게 나왔다.

같은 이유로 **그룹 지주사**도 막아야 했다. "CJ"가 "CJ제일제당"·"CJ ENM" 안에서
잡혀 자회사 목표가가 지주사로 들어갔다(배율 탈락 28건·분산 53%).
전체 상장사 2,765개 목록으로 부정 전방탐색을 만들어 해결했다(→ 탈락 3건·분산 14%).

## 산출하는 값 5개

증권사당 최신 1건, 최근 90일.

| 값 | 쓰는 방식 |
|---|---|
| 증권사 수 | 3곳 미만이면 나머지를 계산하지 않음 |
| 목표가 중간값 | 평균이 아니라 중간값 — 오추출이 남아도 흔들리지 않는다 |
| 상승여력 | 중간값 ÷ 현재가 − 1. **순위로만** 사용 |
| 분산 | 사분위 폭 ÷ 중간값. 낮으면 의견 일치 |
| 상향 비율 | (상향 − 하향) ÷ 증권사 수 |

## 언제 값이 갱신되나 (4단계)

| 단계 | 기준 |
|---|---|
| ① 수집 | 주 1회(월요일) + 월간 실행. 최신 기사부터 90일 전까지. 대형주는 검색어당 1,000건 한도로 약 30일치 |
| ② 한 건으로 묶기 | 같은 증권사가 같은 목표가를 **14일** 안에 다시 내면 같은 리포트(복제) |
| ③ 증권사별 대표값 | 아래 규칙 |
| ④ 종목 값 | 국내 증권사 대표값들의 **중간값**, 증권사 3곳 이상일 때만 |

**③ 증권사별 대표값 규칙**

1. 90일 창 안에서 **복제 2건 이상**(여러 매체에 실린 발표) 중 최신을 고른다
2. 그보다 나중에 나온 **복제 1건짜리**는, **방향 라벨이 값의 변화와 일치할 때만** 채택
3. 복제 2건 이상이 하나도 없으면 그냥 최신

2번이 핵심이다. 나중 기사가 옛 목표가를 다시 인용하는 일이 흔하고(KB증권이 현대차를
120만→90만으로 낮춘 뒤에도 "목표가 극과 극" 기사가 옛 120만원을 언급), 1건짜리는
오추출일 확률도 높다.

실측 근거 (2026-09-12, 90일 창)

- 복제 1건 관측의 **방향 모순율 31%** vs 복제 2건 이상 **14%** — 1건짜리가 2배 더 틀린다
- "복제 2건 이상 우선"으로 최신이 밀린 경우 96건. 그중
  **방향 일치 36건(진짜 갱신) · 모순 22건 · 방향 표시 없음 38건**
- 방향이 일치한 36건은 실제 변경이었다 (삼성전기를 NH투자·신한투자가 나란히
  300만 → 220만으로 하향). 그래서 이것만 통과시킨다
- 기사 안에 "A원에서 B원으로"가 함께 적힌 605건의 방향 모순율은 **0.8%** —
  파싱 자체는 신뢰할 만하고, 문제는 기사 간 대조에서 생긴다

즉 **한 증권사의 숫자가 바뀌려면**: 새 목표가가 (a) 2곳 이상 매체에 실리거나,
(b) 1곳이라도 "상향/하향" 표시가 값의 방향과 맞아야 한다. 둘 다 아니면 이전
확정 발표가 90일 창에서 빠질 때까지 유지된다.

## 읽을 때 주의

**상승여력 중앙값이 +45%다.** 목표가는 체계적으로 낙관적이고(한국 매도 의견 1% 미만),
**주가가 급락한 뒤에는 목표가가 늦게 따라와 상승여력이 부풀려진다.**
현대차가 그 예다 — "75만원 찍고 30% 급락"한 뒤에도 목표가 중간값은 72만원이었다.
그래서 상승여력은 "얼마나 오를지"가 아니라 **"애널리스트가 목표가를 고친 뒤 주가가
얼마나 빠졌는지"**를 재는 쪽에 가깝다. 절대값 대신 종목 간 순위와 상향·하향 방향을 본다.

증권사끼리 값이 비슷한 것도 독립적인 확인이 아니다(동조화). 그래서 중간값의
신뢰도를 높이는 근거로 쓰지 않고, **분산 자체를 따로 신호로** 본다.

## 어디에 반영했나 — 점수에는 넣지 않는다

과거 컨센서스 데이터가 없어 백테스트를 할 수 없다. 검증 안 된 신호를 검증된
가중치에 넣으면 모멘텀(IC −0.003)·3년 CAGR(−0.029) 때와 같은 실수가 된다.

**역할 A — 참고 정보**
- 종목 노트 `## 증권사 시각` — 증권사별 목표가·상향하향·기사 링크
- 월간 노트 `## 지표 vs 증권사 컨센서스` — 내 순위 vs 컨센서스 순위, 갈리면 ⚠
- 수동 입력(`_입력/컨센서스.csv`)은 뉴스로 안 잡히는 종목 보충용으로만 남김

**역할 B — 검증 대상** (**성과추적**에 종이 규칙 3개 추가, 2026-09-12 시작)
- `컨센 상승여력` 상위 5
- `컨센 상향비율` 상위 5
- `복합성장∩상향` — 우리 성장주 점수 상위이면서 증권사도 상향 중

매달 쌓으면 12개월 뒤 기록으로 판정한다. 통과하면 그때 게이트나 동점 처리용으로
검토하고, 그때도 가중치에는 넣지 않는다.

## 주 1회 자동 수집 (2026-09-12 설정)

Windows 작업 스케줄러에 등록했다. 대형주는 한 번에 약 30일치만 오므로
주 1회 쌓아야 90일 창이 채워진다.

| 항목 | 값 |
|---|---|
| 작업 이름 | `주식스크리너_증권사목표가_주간수집` |
| 실행 | 매주 **월요일 09:00** (PC가 꺼져 있었으면 켜진 뒤 곧 실행) |
| 실행 파일 | `scripts/weekly_news.bat` |
| 로그 | `screener/logs/news_weekly.log` (실행마다 덧붙임) |
| API 사용 | 1회 약 400건 → 월 1,700건. 한도 775,000건의 0.2% |

확인·조작 (PowerShell)

```powershell
Get-ScheduledTaskInfo -TaskName "주식스크리너_증권사목표가_주간수집"   # 마지막 결과·다음 실행
Start-ScheduledTask   -TaskName "주식스크리너_증권사목표가_주간수집"   # 지금 한 번 돌리기
Disable-ScheduledTask -TaskName "주식스크리너_증권사목표가_주간수집"   # 잠시 멈춤
Unregister-ScheduledTask -TaskName "주식스크리너_증권사목표가_주간수집"  # 삭제
```

마지막 결과가 `0`이면 정상, `267009`는 실행 중이라는 뜻이다.
월간 실행(`run_monthly.py`)도 4단계에서 같은 수집을 하므로, 주간 작업이 며칠
밀려도 월간 결과에는 구멍이 생기지 않는다.

## 한계

1. **대형주는 약 30일치만 본다.** 검색어당 1,000건 한도 때문이다.
   자주 돌릴수록 누적되어 90일 창이 채워진다(월 1회보다 주 1회가 낫다).
2. **중소형주는 기사가 적다.** 51종목이 증권사 2곳 이하다.
3. **정확도를 상시 잴 기준이 없다.** 네이버 컨센서스와의 대조는 수동이다.
   분기에 한 번쯤 2~3종목을 다시 맞춰보는 게 좋다.
4. 증권사 주식(삼성증권·키움증권 등)은 이름이 애널리스트로도 등장해 노이즈가 크다.
