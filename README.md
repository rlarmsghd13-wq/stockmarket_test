# 펀더멘털 스크리너 — 한국 대형주

재무제표로 한국 대형주를 채점해 **가치투자·성장주** 두 전략으로 종목을 고른다.
차트 패턴은 쓰지 않는다.

> **먼저 읽어주세요.** 8년 백테스트에서 **가치투자는 벤치마크에 크게 졌습니다.**
> 성장주는 이겼지만 낙폭이 지수의 두 배였고, 결과는 전부 인샘플입니다.
> 이 저장소는 "작동하는 전략"이 아니라 **검토받고 싶은 실험**입니다.
> 어디가 틀렸는지 찾아주시면 가장 도움이 됩니다.

---

## 1. 알고리즘

```
2,700개 상장사
   │  시총 5,000억+ · 60일 평균 거래대금 50억+ · 시총 상위 200
   ▼
유니버스 200종목
   │  트랙 분리: 일반 / 금융 / 제약바이오 / 지주
   │  (은행에 부채비율을 들이대면 전부 탈락한다)
   ▼
지표 → 부문 점수 (트랙 안 → 업종 안 2단계 백분위)
   │  밸류에이션 · 수익성 · 성장성 · 안정성
   ▼
전략별 가중합 + 게이트 + 감점
   ▼
78점↑ 매수 · 62~78 보유 · 52~62 축소 · 52↓ 매도
```

### 왜 백분위인가

PER 12는 싼가? 은행이면 비싸고 반도체 장비면 싸다. 절대 임계값을 쓰면 특정 업종이
상위를 통째로 점령한다. 그래서 **같은 트랙·같은 업종 안에서의 등수**만 쓴다.
업종 표본이 8종목 미만이면 트랙 전체로 폴백한다 (`src/grading.py`).

### 부문 구성

| 부문 | 지표 |
|---|---|
| 밸류에이션 | PER 30 · PBR 25 · EV/EBIT 20 · PSR 10 · FCF수익률 15 |
| 수익성 | ROE 35 · 영업이익률 25 · ROIC 20 · ROA 10 · 순이익률 10 |
| 성장성 | 매출성장 35 · 영업이익성장 35 · 순이익성장 20 · 성장변동성 10(역) |
| 안정성 | 부채비율 30(역) · 유동비율 20 · 영업CF/순이익 25 · FCF/순이익 25 |

금융·제약·지주는 지표셋이 다르다 (`TRACK_OVERRIDE`). 결측 지표는 빼고 가중치를
재정규화한다 — 중간값으로 채우지 않는다.

### 전략 가중치

| | 밸류 | 수익 | 성장 | 안정 |
|---|---|---|---|---|
| 가치투자 | 50 | 30 | 10 | 10 |
| 성장주 | 35 | 30 | 25 | 10 |

모멘텀 부문은 **가중치 0**이다. 97개월 검증에서 IC −0.003으로 예측력이 없었고
기간을 나누면 부호가 뒤집혔다.

### 게이트 — 점수와 무관하게 탈락

**가치투자** 3년 중 영업적자 2회↑ / 부채비율 200%↑ / 3년 중 FCF흑자 2회↓ /
ROE 8%↓ / 밸류에이션 상위 40% 밖 / 퀄리티 상위 50% 밖

**성장주** 성장성 상위 20% 밖 / 최근 4분기 중 매출성장 3회↓ / 유동비율 100%↓ /
시총 3,000억↓

현재 199종목 중 가치 25개, 성장 12개가 통과한다.

### 매도 — 시장 탓이면 보류

점수가 기준 아래로 내려가도, **같은 트랙의 40% 이상 또는 같은 업종의 50% 이상이
함께 악화**했으면 시장 요인으로 보고 매도를 미룬다 (최대 6개월). 단 그 회사의
절대 지표가 25% 넘게 나빠졌으면 회사 문제로 보고 판다. `src/regime.py`

## 2. 미래 정보를 막는 장치

백테스트가 조용히 거짓말하는 경로를 막아둔 것들이다.

| 위험 | 대응 |
|---|---|
| 미공시 재무를 미리 씀 | 공시 접수일(`rcept_dt`)이 기준일 이전인 것만 사용 |
| 사업보고서 접수일 오인 | 보고서명의 `(YYYY.12)` 기간 표기로 매칭 |
| 지금 살아남은 회사만 봄 | 그 시점의 상위 200을 재구성 (누적 444종목) |
| 상장폐지 누락 | 마지막 거래일 종가까지 반영 |
| 시세 데이터 결손 | 매 실행 시 표본 급감 경고 (`btdata.check_coverage`) |

마지막 항목은 실제로 사고가 났었다. 과거 시세가 2023-06에서 끊긴 채 돌아가
2023-07 이후 표본이 423 → 190종목으로 줄었고, **벤치마크가 두 배로 부풀려져
있었다.** 복구 후 벤치마크 총수익이 +211% → +103%로 반토막 났다.

## 3. 백테스트 결과 (2018-06 ~ 2026-06, 97개월)

매월 점수 상위 5종목 동일가중, 편도비용 0.35%.

| | 총수익 | CAGR | MDD |
|---|---|---|---|
| 유니버스 동일가중 (벤치) | +103% | 9.2% | −35% |
| 시총가중 (지수 근사) | +256% | 17.0% | −33% |
| **가치투자** | **+9%** | 1.1% | **−69%** |
| **성장주** | +607% | 27.4% | **−67%** |

**최근 2년(2024-07~)을 빼면** 시장 자체가 6년간 +1%였다. 그 구간에서
가치투자는 −59%, 성장주는 +94%였다.

### 단일 지표와 비교하면

| 신호 | 총수익 | 두 구간 모두 벤치마크 초과? |
|---|---|---|
| 성장성 부문 단독 | +566% | **O** |
| 수익성 부문 단독 | +390% | **O** |
| 복합 성장주 | +253% | 후반만 |
| 복합 가치투자 | +60% | 후반만 |
| PBR 저평가 단독 | +12% | — |

**복합 점수가 단일 부문보다 나빴다.** 그리고 PBR은 IC(전 종목 순위상관)로는
+0.087로 1위인데 상위 5종목을 실제로 사면 하위권이다 — IC와 계좌 성과가 다른
것을 잰다.

자세한 내용은 [`docs/백테스트.md`](docs/백테스트.md).

## 4. 실행

```bash
pip install -r requirements.txt
cp .env.example .env        # 키를 채운다
python scripts/run_monthly.py
```

`run_monthly.py` 가 6단계를 순서대로 돈다.

```
[1] 지표 계산   [2] 등급화   [3] 전략 스코어
[4] 증권사 목표가 수집 (선택)   [5] 볼트 갱신   [6] 성과 추적
```

재무·시세는 받아둔 것을 쓴다. 새 분기 공시가 나왔을 때만 `03`/`05`를 다시 돌린다.

### 검증·분석 스크립트

| 스크립트 | 내용 |
|---|---|
| `09_validate.py` | IC·5분위 — 지표 방향 확인용 |
| `14`~`16` | 게이트 검증 |
| `17_backtest.py` | 계좌 단위 백테스트 |
| `18_factor_race.py` | 단일 지표 vs 복합 점수 |
| `22_dca_backtest.py` | 적립식 + 손절·분할익절 |
| `23_turnover.py` | 종목 순환율 |

### 필요한 키

| 키 | 용도 | 없으면 |
|---|---|---|
| `DART_API_KEY` | 재무제표 | 필수 |
| `KRX_ID`/`KRX_PW` | 시세 (pykrx 1.2.8+) | 필수 |
| `NAVER_CLIENT_ID`/`SECRET` | 증권사 목표가 수집 | 그 단계만 건너뜀 |

## 5. 검토받고 싶은 것

친구/동료가 봐준다면 이 순서로 봐주시면 가장 도움이 됩니다.

1. **미래 정보가 새는 곳이 더 있는지** — `src/panel.py`, `src/btdata.py`가 핵심
2. **가중치·게이트 임계값이 과최적화인지** — 전부 같은 데이터로 골랐습니다
3. **복합 점수가 단일 부문보다 나쁜 이유** — 부문 간 상관? 가중치 문제?
4. **가치투자를 접어야 하는지, 아니면 밸류에이션 축을 다시 설계해야 하는지**
5. **거래비용 0.35%(편도)가 현실적인지**

## 6. 알려진 한계

- 모든 백테스트가 **인샘플**이다. 가중치·게이트·손절값을 같은 기간으로 골랐다
- 배당이 빠져 있다 (전략·벤치마크 양쪽 다)
- 시가총액은 그 시점 주가 × 스냅샷 주식수 근사다
- 거래대금은 `close_adj × volume` 근사라 액면분할 구간에서 왜곡된다
- 증권사 목표가는 2026-09부터 모으기 시작해 **과거 검증이 불가능**하다
- 일부 종목의 PER·PBR이 통화 문제로 어긋났었다 (두산밥캣은 USD 공시) —
  `metrics.MIXED_UNIT_METRICS`로 비우도록 고쳤다

## 7. 데이터 출처와 규칙

| 출처 | 용도 | 제약 |
|---|---|---|
| DART OpenAPI | 재무제표 | 일 20,000건 |
| KRX (pykrx) | 시세·유니버스 | **0.35초 간격 · 일 800건 · 동시 실행 금지** |
| NAVER API HUB | 뉴스 인용 목표가 | 월 775,000건 |

KRX는 과도한 조회로 **24시간 IP 차단을 당한 적이 있다.** `src/krx.py`의 스로틀을
낮추거나 두 작업을 동시에 돌리지 말 것.

한경컨센서스·네이버 금융·네이버 뉴스는 `robots.txt`가 자동 수집을 전면 금지한다.
그래서 목표가는 **공식 검색 API로만** 받고 기사 본문은 가져오지 않는다.
